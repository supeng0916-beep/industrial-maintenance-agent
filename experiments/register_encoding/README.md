# 跨寄存器编码小实验

2026-09-17。离线固定数据实验，不连接设备、不更改现有四测点地址或数据库。

运行：

```bash
uv run --locked python experiments/register_encoding/demo.py
```

## 先看整数

点位约定uint32、高16位在前、倍率0.001℃：`[1,57920]`。

`1 * 65536 + 57920 = 123456`，得到123.456℃。颠倒两项得到3795845.121℃。

## 再看浮点

点位约定IEEE754 Float32、高16位在前、寄存器内高字节在前、直接表示℃：`[0x4282,0x999A]`（十进制 `[17026,39322]`）。

```python
raw_bytes = struct.pack('>HH', *registers)
value = struct.unpack('>f', raw_bytes)[0]
```

- pack：将两个16位无符号整数变为四个字节；H代表16位无符号整数，HH表示两个。
- `>`：按大端字节顺序处理；本例还通过列表顺序约定高16位字在前。字节顺序与两个寄存器的字顺序要分别核对。
- unpack：将同一组四字节按Float32解释；f代表32位浮点数。
- `[0]`：unpack返回元组，这里取唯一一个解析结果；不是寄存器地址。

正确得到65.300003051758℃，显示一位小数为65.3℃。小差异来自二进制浮点表示精度，不是通信失败；不要求背IEEE754公式。

颠倒两寄存器得到约-1.59500891e-23℃（非常接近0的负数）；误按uint32得到1115855258。错误解析不一定总是几百万，也可能看起来很小甚至合理。不能仅凭值落在正常范围就证明解析正确。
