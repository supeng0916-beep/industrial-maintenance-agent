# 第二次增量：持续采集与 SQLite

按用户已经批准的范围，在当前项目直接实施，不另建用户任务。

## 设计与约束

- 保持 Python 3.11.15 / PyModbus 3.11.3，SQLite 使用标准库。
- `modbus_reader.py` 提供 `read_temperature(port)`，返回原始值和换算温度；失败抛异常，连接总是关闭。一次性客户端和采集器共用此函数。
- `storage.py` 管理建表、短事务写入与限量查询。`measurements` 含统一八字段及自增 ID；`collection_events` 单独保存失败时间和原因。
- `collect_temperature.py` 默认每秒尝试一次；`--count 0` 持续，正整数表示尝试次数（成功和失败均计数）。每轮最多一次请求，无库内请求重试。慢请求不补发追赶。
- 完成有限次数后，有通信失败则退出 1，否则 0；数据库异常立即退出 1；Ctrl+C 退出 130并关闭连接。
- `query_history.py` 只读打开已有文件，默认查询 motor-a/temperature 最新 10 条；上限 1000，时间降序、ID 降序。`--events` 查询失败事件。
- 时间为采集端完成尝试时的 UTC，带 +00:00；source_time 为 NULL；成功 quality=good，protocol=modbus_tcp。
- 只增加持续采集、存储和命令行查询，不动 docs/learning。
