# 后续学习计划：从检索实验到完整助手

状态：2026-09-18。六组主题拆为十个短单元；单元可以拆开或合并，不按“回答了十道题”算学完。不要求每个单元结束才能开发，用户已允许先开发再讲解。

## 已掌握与不必重讲

- Modbus寄存器/偏移/倍率/跨寄存器编码，批量读取不等于同步测量；OPC UA NodeId/namespace、数据类型、质量、源时间、读取/订阅/采样/发布/队列/保活。
- 读取失败不伪造温度；0不等于失败；最后有效值不等于当前值；设备健康与数据质量不同。
- SQLite历史和失败事件、工具查询时间范围；SQL基础已学，不逐句讲SELECT。
- 告警持续计时、断档重新累计、回差、持久化、设备隔离；数据不可信不能推进或解除。
- 文档适用性、未知型号不是通用、切块语义完整、token/embedding/索引基本职责、同维向量不代表同空间。
- 检索与重排区别；最新回答已正确说明“重排无法补回候选集合外的证据”。无需再问同题。

上述来自历史问答/实验，表示已有理解，不等于已独立实现每个模块。最后用一次综合排错检验迁移能力即可。

## 教学方法

每次：一个项目现象 → 一张小图或不超过约20行关键代码 → 一项预测/解释/修改任务 → 反馈 → 记录。术语首次出现给中文含义；不要连续出大量只能答“不能”的题。答对后进入下一层；答错先针对一个缺口解释，再换一个例子检验。

用户说“继续开发”时先推进小工作包，不以无限教学问答阻塞。用户说“学习”时使用已经实现的代码/结果，不把计划接口当现成功能。每次收尾明确开发进度与学习进度分别是什么。

## 十个单元

| 单元/对应开发 | 学习目标 | 真实材料/活动 | 掌握标准 |
| --- | --- | --- | --- |
| L1 检索诊断 / D1 | 区分缺文档、缺片段、排位低、标注不完整 | 看R17/R29/R34的候选；用户给一题归因并说下一步检查 | 能指明证据在哪里，提出可验证假设，不把所有问题都归因模型弱 |
| L2 对照实验 / D1～D2 | 单变量、开发集/已观察保留集、退步题与偏差 | 对比中英文探针；解释为何3/3不能代表整体效果 | 能设计固定项/变化项，指出人工改写读过答案的偏差；能算指标分母 |
| L3 工具合同 / D3 | 数值工具与文档工具各管什么 | 读ReadOnlyTools.invoke和检索包装；画问题到工具输入/输出 | 能为“昨天均温+维护建议”列两个正确工具及参数，缺时间先补足 |
| L4 Agent循环 / D4～D5 | 模型选择工具、工具执行、模型基于结果回答 | 展示一次真实调用轨迹，用户标注模型/程序/数据库各自动作 | 能指出模型没有直接读数据库或执行任意SQL；调用失败不等于没记录 |
| L5 证据回答 / D5～D6 | 事实、推测、建议、未知与引用边界 | 对比同一问题的有依据/过度推断回答；纠正其中两处 | 数值引用当次工具；文档引用支持实际陈述；不混淆典型表值与现场值 |
| L6 失败与预算 / D5～D6 | 6次调用/工具5秒/总60秒与未完成语义 | 模型不可用、工具超时、无资料、超预算四个轨迹 | 能解释该保留哪些已取得证据，以及不能继续声称什么 |
| L7 文档作为不可信输入 / D6 | 资料内容不能变成系统执行指令 | 在隔离夹具放“忽略规则/修改设备”的段落，检查允许工具集合 | 能说明允许工具/程序边界与提示词的区别；识别资料中的指令不是授权 |
| L8 页面联调 / D7～D8 | 前端请求、后端编排、证据时间与引用 | 浏览器查看请求和错误响应；用户解释一次模型超时页面 | 能区分助手失败、API失败、采集失败和设备离线；历史查询范围不等于当前时刻 |
| L9 分层验收 / D9 | 工具数值、检索证据、最终回答分别验证 | 用户为一个坏答案定位层次并写预期结果 | 能辨别正确数字但错设备/错时间/错来源仍是不合格 |
| L10 独立演示与排错 / D10～D12 | 从启动到解释整个系统 | 用户运行隔离演示，修改一项查询或配置并说明影响 | 能完成“现象→查证→定位→修复→复验”，并解释至少一个限制 |

## 推荐衔接顺序

1. 开发D1～D2先行；教学L1～L2用实际结果，不重跑已做探针。
2. D3可与模型选择准备并行；L3～L4解释工具与Agent。模型选型缺信息时问一次：本地还是API、已有可用服务及预算；不要要求把密钥发在聊天中。
3. D5～D6完成后讲L5～L7，再进入页面D7～D8/L8。
4. D9对应L9，最后D10～D12对应L10和课程交付。

粗略排课可按6～10次学习安排，每次只处理1～2个单元；这不是交付期限或已验证工时，实操遇到缺口就拆分。不要因为回答快就跳过最后的独立实验。
