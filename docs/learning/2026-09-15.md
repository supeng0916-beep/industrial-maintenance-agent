## 1. 数据从哪里来

模拟器 → Modbus TCP → 采集器 → SQLite → 后端 API → 浏览器。

模拟器提供原始值，采集器读取并转换、保存，后端查询，页面展示。今天讨论的是目标架构，数据库、后端和页面尚未实现。

## 2. 寄存器、原始值与倍率

- 寄存器地址：读取哪个位置；第一项实验使用保持寄存器协议地址 0。
- 原始值：模拟器保存的数，例如 653。
- 倍率：项目约定的转换规则。温度 = 原始值 × 0.1，单位为 ℃。
- 例子：653 → 65.3℃；728 → 72.8℃；681 → 68.1℃。
- 数字本身不包含温度单位；倍率与单位来自点位约定。

## 3. 采集与页面独立

采集器像记录员，数据库像记录本，浏览器像查看记录的人。

- 新开一个页面，增加的是查询请求，不应该启动新的采集循环。
- 关闭所有页面，只要模拟器和采集器正常运行并成功写库，历史仍会积累。
- 历史记录可帮助回看异常前后的变化，但仅凭趋势不一定能确定故障原因。

## 4. 采集失败意味着当前值未知

| 情况 | 含义 | 应如何记录 |
|---|---|---|
| 成功读到原始值 0 | 本次测量结果为 0℃ | 保存测量值与采集时间 |
| 超时或通信失败 | 本次未获得温度 | 记录采集失败，不写入假温度 |

失败后不能把上次的 65.3℃ 配上新时间重新保存，否则会伪造温度稳定的证据。即使温度实际上没有变化，也没有这次成功测量来证明它。

## 5. 两种时间与两种状态

- 最后成功采集时间：真正读到数据的时间，只在成功采集后更新。
- 最近采集尝试时间：尝试通信的时间，失败也可以更新。
- 通信状态：最近请求是否成功等通信信息；具体在线判定规则需要在实现中明确。
- 数据新鲜度：最后成功数据距离现在多久。

项目教学配置为超过 5 秒没有新数据则过期，比较规则为 `数据年龄 > 5`。这是项目配置，不是 Modbus 协议规定。

```python
# 核心判断片段：假设 now 和 last_success_at 都是带时区的 datetime，且已有成功记录
data_age_seconds = (now - last_success_at).total_seconds()
is_stale = data_age_seconds > 5
```

尚无成功记录时，应该显示“暂无数据”，不能套用一个不存在的时间。

## 6. 今日易错点：恢复后是否仍然过期

最初认为 12:00:07 成功读取新温度后仍然已过期。纠正：过期描述当前保留数据的年龄，不是永久故障标记。新数据到来后重新计算；之前的失败事件仍可保留。

| 当前时刻 | 最后成功时间 | 最后已知温度 | 新鲜度 |
|---|---|---|---|
| 12:00:00 | 12:00:00 | 65.3℃ | 未过期 |
| 12:00:06 | 12:00:00 | 65.3℃ | 已过期 |
| 12:00:07，读取成功 | 12:00:07 | 68.1℃ | 未过期 |
| 12:00:13，其间无新数据 | 12:00:07 | 68.1℃ | 已过期 |
