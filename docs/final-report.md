# 最终交付报告：工业设备智能运维Agent（课程项目）

日期：2026-09-20。本报告每项成绩链接实际验收证据；未实现的能力如实标注。项目全程开发记录见[项目计划v0.2](project-plan-v0.2.md)文末与[12工作包计划](superpowers/plans/2026-09-18-remaining-development.md)勾选。

## 1. 背景与范围

课程目标：为工业设备运维构建一个"可信只读"的智能助手原型——多协议采集监控 + 基于真实资料的检索问答，回答必须可溯源、证据不足必须拒答、绝不伪造现场值。范围限定：本地教学仿真数据（非真实硬件）、DOE公开资料（非产品手册）、单Agent（非多智能体）。

## 2. 架构与数据流

```
Modbus模拟器(15030) ─┐
                      ├→ 采集器(1s轮询/OPC UA订阅) → SQLite(带微秒UTC时间戳)
OPC UA模拟器(4840) ──┘                                    │
                                                           ├→ FastAPI只读查询(/api/*) → React看板
                                                           └→ /api/assistant/chat → AssistantService
                                                    ┌──────────┴──────────┐
                                              四只读工具(程序执行)      LangChain适配
                                           status/history/alarms/    deepseek-chat(云) 或
                                           DOE文档检索(E5索引)        本地Ollama(备胎)
```

关键设计：**模型只产出意图，工具结果一律程序执行获得**；助手故障不影响监控链路（未配置模型时仅助手路由503）。

## 3. 点位、质量与告警规则

- motor-a（Modbus TCP）：温度/电流/转速/运行状态四测点；motor-b（OPC UA）：温度单测点，read/subscribe二选一，质量Good+源时间新鲜+严格递增才入有效测量。
- 告警（教学规则teaching_only）：>80℃持续达确认时长触发，<78℃恢复（回差）；待确认态只显示服务端已观测时长；断线/过期不作为恢复证据。

## 4. 协议差异要点

Modbus轮询无源时间概念，OPC UA带源时间戳/质量码/服务器时间——后者因此多了质量与新鲜度校验层与订阅重复投递防护。这决定了两个设备的"有效数据"语义不同，助手回答按设备分别呈现。

## 5. Agent/RAG选型与三层证据

- **检索**：15份DOE Motor Systems Tip Sheets（2012英文，30物理页）→ v4切块→ multilingual-e5-small本地嵌入→ Chroma本地索引（113块）。语料真实、来源可查（manifest含许可与来源注册）。
- **生成**：DeepSeek `deepseek-chat`（OpenAI兼容端点，密钥仅存后端.env）；本地Ollama路线保留为无网对照（适配器可切换）。选型过程含真实对照实测：本地qwen2.5:7b表格取数失败 vs 云API成功（见§7）。
- **三层评测**：①检索层（Hit@k，锚点计分）；②流程层（工具路由/预算/白名单，程序断言）；③语义层（人工复核场景集）。

## 7. 失败案例（比成功更有教学价值）

1. **本地7B表格取数失败**：检索候选已含答案块（86%原文），qwen2.5:7b提取不出反而编造"94%~95%"——模型能力边界不能靠提示词完全弥补；换deepseek-chat后同场景正确回读整行。
2. **跨供应商协议bug**：Ollama宽松放行缺失的assistant(tool_calls)回合，DeepSeek严格拒绝——单供应商验收会掩盖协议缺陷。
3. **程序断言的边界**：D9前四轮"违规"全部为断言误报（否定语境、规则阈值vs读数、澄清优先路径）——自然语言语义必须配人工复核。
4. **状态徽章依赖模型自评**：诚实拒答内容常被标为answered——观察项，改进方向是程序后处理。
5. **检查集首点丢失**：夹具时间格式缺微秒暴露文本比较的格式不变式（生产采集器无此问题）——写进runbook。

## 8. 复现方式

见[运行手册](runbook.md)：`uv sync --locked` + `npm --prefix frontend ci` + `.env`三变量 + `run_dashboard.py`；测试与全部验收命令在内。**检索命中≠回答正确**：Hit@k是证据召回，回答质量由场景集+人工核查保证。

## 9. 限制（如实声明）

- 语料：15份DOE 2012年英文通用指南；不含中文厂家手册、不含现行法规；型号适用性一律未核实。
- 检索：中文提问对英文语料存在语言差（改写诊断显示英文查询显著更优，但可部署的自动翻译需额外模型且未实施——D4决策记录了该取舍）。
- 模型：单模型单次运行有随机性；24场景双跑已覆盖关键边界但样本仍小；不构成一般工业可靠性声明。
- 数据：教学仿真，非现场实测；助手不提供已确认故障根因，只给可能因素与排查建议。
- 部署：Vercel仅承载前端，后端需自建（用户自行处理；`.gitignore`已确保密钥与用户数据不入库）。
- 已知观察项：citations模型不主动产出（程序校验兜底）；D9报告观察项1-4。
