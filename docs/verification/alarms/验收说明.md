# M2 第一小步：温度回差告警

## 范围与语义

仅实现 motor-a / temperature 的即时回差规则：**有效新温度 >80℃ 触发；已有告警时 <78℃ 恢复；恰好80℃或78℃保持原状态**。连续高温只有同一次告警，恢复后再高温产生新记录。80/78是教学配置，不是设备安全限值。本次不代表整个M2完成；持续超限、多测点尚未实现。

采集器独立运行，不依赖页面。每次成功采集在一个短事务内保存测量、触发/恢复证据和评估位置；失败则全部回滚。数据库保留开始/恢复时间、温度、对应样本ID及该次阈值。时间来自本地采集完成时间，设备源时间仍为空。已激活告警重启后继续，唯一索引阻止重复未解除记录。

`current` 与 `active` 分开：

| current | 含义 |
| --- | --- |
| not_enabled | 旧库无告警表或无规则状态，明确未启用 |
| unknown | 未评估新样本、通信失败、过期、样本未经规则评估或未来时间；不能判断当前温度 |
| active | 新鲜有效样本支持规则判断，存在未解除告警 |
| clear | 新鲜有效样本支持规则判断，无未解除告警；不代表设备健康 |

`active` 可与 `unknown` 同时存在。失败和过期不会更新恢复字段。前端接口失败时保留证据并标为历史快照；按单调时钟累计请求和等待时间，慢历史查询不会把已过期状态重新显示为当前已知。

新版采集器启动才创建告警表。API通过SQLite只读连接查询，不迁移、不写库；旧测量不回放。规则启用后第一次新采集才建立判断，空状态不能伪称无告警。旧版采集器继续写未评估样本时，API保守显示unknown。

## 接口

- `GET /api/devices/motor-a/latest` 增加 `alarm`，和温度/采集状态使用同一个SQLite只读快照。
- `GET /api/devices/motor-a/alarms` 返回相同告警对象。
- 字段：enabled/current/active/history/total/limit/evaluated_measurement_id/rule。
- 历史按告警ID降序，最多20条，total为总条数；本步无分页和删除接口。

## 自己动手运行

保持现有5175/8010/15030服务不动。另开终端，在项目根目录运行以下命令（若所选端口被占用，启动器会报错，另选端口即可）：

```bash
uv run --locked python run_dashboard.py --db data/alarm-practice.sqlite3 --web-port 5176 --api-port 8011 --modbus-port 15031 --raw 810
```

打开 http://127.0.0.1:5176 ，新温度81℃触发告警。刷新页面或持续等待仍只有一条。

在**刚才这个练习终端**按Ctrl+C停止本次服务，保持相同数据库和端口重启：

```bash
uv run --locked python run_dashboard.py --db data/alarm-practice.sqlite3 --web-port 5176 --api-port 8011 --modbus-port 15031 --raw 780
```

78℃仍未解除。再次Ctrl+C后将末尾改成 `--raw 779`：77.9℃恢复。再改回 `--raw 810`：新建第二次告警。每次启动都保留同库历史。

查询：

```bash
curl http://127.0.0.1:8011/api/devices/motor-a/alarms
```

上述练习使用专用新库，不使用 `data/my-learning.sqlite3`。本次开发验证全部使用临时库和独立端口；没有停止已有用户服务。
