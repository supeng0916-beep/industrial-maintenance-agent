# M4.1 只读业务工具验收

三个工具已实现，可直接通过 Python 或 CLI 调用。HTTP 最新值接口和工具共用事实读取代码；本步未接入模型、LangChain、向量库、RAG 或助手界面。

## 调用方式

在项目根目录运行，`--db` 是应用配置。下面只读取已有练习库；时间范围应换成实际练习时段。

```sh
.venv/bin/python -m assistant --db data/m3-subscription-practice.sqlite3 get_device_status --params '{"device_id":"motor-b"}'
.venv/bin/python -m assistant --db data/m3-subscription-practice.sqlite3 query_metric_history --params '{"device_id":"motor-b","metric":"temperature","start":"2026-09-17T00:00:00+08:00","end":"2026-09-18T00:00:00+08:00","limit":1000}'
.venv/bin/python -m assistant --db data/m3-subscription-practice.sqlite3 list_alarms --params '{"device_id":"motor-b","start":"2026-09-17T00:00:00+08:00","end":"2026-09-18T00:00:00+08:00","status":"all","limit":1000}'
```

Python 入口为 `assistant.tools.ReadOnlyTools(db_path)` 的同名方法，或 `invoke(name, arguments)`。成功返回 `{"ok":true,"data":...}`；失败返回 `{"ok":false,"error":{"code":...,"message":...}}`，不能将错误解释成“没有告警/没有数据”。CLI 成功退出码为 0，工具错误或非法 JSON 为 1，argparse 命令格式错误为 2。退出码与设备运行状态枚举是不同概念；正式运行状态仍只有 0＝停止、1＝运行。

## 参数和结果含义

| 工具 | 必填参数 | 可选参数 | 主要结果 |
| --- | --- | --- | --- |
| `get_device_status` | `device_id` | 无 | 设备、全部支持指标、最后有效记录、采集/源质量状态、置信度、温度告警 |
| `query_metric_history` | `device_id, metric, start, end` | `limit=1000` | 完整区间统计、有限条明细、截断标记 |
| `list_alarms` | `device_id, start, end` | `status=all, limit=1000` | 相交告警、完整匹配计数、设备全历史计数 |

设备限 `motor-a`、`motor-b`；A 支持 temperature/current/speed/running_state，B 仅 temperature。时间必须带时区，统一转 UTC，起止闭区间且跨度最多 24 小时。limit 必须是 1..1000 的整数（不接受布尔值）；未知工具或额外参数被拒绝。工具参数不能指定数据库路径、SQL 或 shell。

### 当前状态与最后记录

一次调用中的全部指标使用同一 SQLite 快照和同一 `checked_at`。`confidence.state` 为 `no_data`、`unavailable`、`stale` 或 `usable`；usable 仅表示记录在时效范围内，不表示设备健康。失败、未核实或过期仍保留最后有效记录及原时间。

B 继续使用既有源时间、质量、运行世代与订阅证据规则；通信成功或订阅保活不代表测量可用。A 不套用 B 的源时间要求。旧库/外部导入的最新 bad 记录不会覆盖最后 good 值，另存于返回结果 `latest_stored_record`，并使当前可信度不可用。

### 历史统计

按 `collected_at` 筛选 quality=good 的记录；B 的该字段是接收时间，不是源时间。SQL 对完整匹配范围统计 count/min/max/首末观测时间，明细按时间和 id 升序截断，因此极值可能不在返回明细中。空范围 count=0、极值为 null。运行状态只统计枚举次数，min/max 为 null；遗留未知枚举标为 undefined。

统计是已记录样本的极值，不是物理设备实际极值。首末时间不证明连续采集，不按固定频率推算缺失数量或完整率；订阅通知可能不等间隔。

### 告警范围

相交条件为 `started_at <= end AND (recovered_at IS NULL OR recovered_at >= start)`。status 为 active/recovered/all，依据检查时数据库记录是否恢复，而非重建过去某一时刻的状态。

- `total`：时间和 status 筛选后的完整匹配数。
- `matched_active_count`：这些匹配记录中仍未恢复的数量。
- `device_total/device_active_count`：本设备全历史计数，不受查询时间和 status 限制。
- `returned_count/truncated`：实际返回条数与是否截断；明细按开始时间及 id 降序。
- `history_available=false`：旧库没有告警表；不等同于规则停用，也不等同于确认无告警。数据库不可读会返回错误。

保留旧告警原始证据，不补造持续时长。未解除告警不证明设备当前仍超温，缺口期间状态未知。

## 只读与错误边界

每次调用以 SQLite `mode=ro` 打开独立连接并 BEGIN，退出即关闭；不创建缺失数据库、不迁移旧表。事务在结果交给调用方之前结束，不跨模型等待持有连接。

默认共享查询预算 5 秒，SQLite progress handler 每 1000 个虚拟机步骤检查单调时钟，锁等待最多 100ms，退出时再次检查总预算；可配置更短预算，不能超过 5 秒。这不是对操作系统停顿的硬实时承诺，结果 JSON 序列化在事务关闭后执行。

错误代码包括 invalid_parameters、invalid_time、invalid_metric、device_not_found、database_unavailable、query_timeout、invalid_stored_data；损坏的存储时间或不可序列化的非有限值不会伪装成成功。

## 验证与代码入口

测试全部使用临时数据库和独立端口，未操作用户已有服务或学习数据。原始回归输出见 [python-tests.txt](python-tests.txt)，三个真实 CLI 子进程验证见 [cli-smoke.json](cli-smoke.json)：1002 个有效样本只返回 10 条，仍正确统计位于截断外的 -10 和 999。

完整 Python 回归 **136 项通过（71.983 秒）**，包含新增 23 项测试。新增测试覆盖参数拒绝、空/旧库只读、A/B 隔离、质量与源时间、异常记录保留、超过 1000 条的完整统计、枚举、告警相交与计数、并发写入下快照一致、锁等待、SQL 超时和 CLI JSON。独立审阅发现的两项问题已补充失败测试并修复，复核通过。

- `assistant/contracts.py`：白名单和时间/数量契约。
- `assistant/observations.py`：HTTP 与工具共享单指标事实。
- `assistant/query_service.py`：只读快照、执行预算、全指标状态。
- `assistant/ranges.py`：历史与告警完整统计。
- `assistant/tools.py`、`assistant/__main__.py`：结构化调用与 CLI。
- `tests/test_assistant_*.py`：本步验证用例。

本步没有修改 UI，不重复浏览器验收；后续模型与检索集成仍需另行实施。
