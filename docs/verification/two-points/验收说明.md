# M2 下一小步：温度＋电流

## 完成范围

温度与电流一次Modbus批量采集、按metric持久化、独立只读查询和页面展示。温度保持已有“>80℃观测连续至少5秒触发、<78℃恢复”的教学告警规则；电流仅观测，无电流告警。本步不代表整个M2完成，不扩展转速或运行状态。

点位与倍率详见 `docs/protocols/点位表.md`，配置集中在 `points.py`。

## 同轮事务契约

- 一次从地址0读count2；两个结果共享一个 `collected_at`，各自保存metric和单位。
- `save_round`在一个短事务内写温度、评估温度告警、写电流。第二条电流写入失败时，温度、告警及pending一起回滚，不出现半轮成功。
- 通信失败不写任何测量，而是为temperature/current写同时间的两条失败事件，并清温度pending；三者同事务。不能更新旧测量的时间，不能补0。已active温度告警不会因通信失败解除。
- DB写入错误使采集器停止，不伪称通信失败或采集成功。已保存历史仍保留，后续查询随时间过期。
- `save_measurement`、`save_failure`原单温度入口保留供历史/既有调用使用；新版采集器只调用整轮入口。无需改动measurements表结构。

## API兼容契约

| 请求 | 行为 |
| --- | --- |
| `GET /api/devices` | metrics声明temperature/current；原status字段仍为温度状态，不是所有指标的总状态 |
| `GET /api/devices/motor-a/latest` | 默认temperature，原消费者兼容 |
| `GET /api/devices/motor-a/latest?metric=current` | 电流最新测量与电流自身失败/新鲜度，alarm=null |
| `GET /api/devices/motor-a/history?metric=current&from=...&to=...` | 只返回电流；省略metric仍默认温度；原时间/条数约束不变 |
| `GET /api/devices/motor-a/alarms` | 仍仅温度告警 |

每个metric的has_data、last_attempt_status、collected_at、age/is_stale均独立查询。温度持续更新不能使旧电流看起来新鲜。未知metric返回422，未知设备404。

GET只读，不建库、不迁移、不补测量。新API读取旧温度库时电流measurement=null、has_data=false、is_stale=null，历史为空；不是0A。旧API的devices.metrics不包含current时，新页面不发电流请求并显示“未提供电流”。

页面保留整轮查询快照策略：任何已支持指标的接口失败，都保留上一轮完整快照并标未核实。成功响应分别查询两指标，因此页面两条“最新”记录可能来自相邻采集轮，必须看各自原采集时间；数据库每个采集轮的两条记录仍共享同一时间。此步不提供跨多个HTTP请求的一致快照承诺。

历史选择器每次只画一个metric，A和℃不混用纵轴。电流保留2位小数，0.00A是有效零读数，暂无样本显示“—”。状态每秒重检收到记录后的经过时间；接口失效、时间冲突和过期不表示设备健康。

保持现有5175/5176/5177、8010/8012/8013、15030/15031/15032的练习服务不动，项目根目录另开终端：
