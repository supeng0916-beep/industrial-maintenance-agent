# M3第一小步：OPC UA 电机B主动周期读取

范围：电机B单个温度点进入统一SQLite、持续温度告警、只读API和看板。电机A仍走Modbus四点采集。本步不含正式订阅、订阅断线恢复或生产认证，不代表整个M3完成。旧 `experiments`、学习笔记和用户数据库未修改。

## 点位与时间约定

| 项目 | 约定 |
| --- | --- |
| Endpoint | `opc.tcp://127.0.0.1:4841/motor-b/` |
| NamespaceURI | `urn:industrial-maintenance:motor-b` |
| Identifier | String `MotorB.Temperature` |
| 类型、单位 | 标量Double，℃；单位为本项目教学约定 |
| 源测量生成 | 模拟器每0.5秒生成一条带新SourceTimestamp的测量，数值可不变 |
| 主动读取 | 默认每1秒读取完整DataValue；每轮建立会话并按URI解析namespace index |
| 告警 | >80℃有效观测连续至少5秒触发，<78℃恢复；相邻有效采集间隔≤1.5×interval |

客户端没有写死 `ns=2`，`--extra-namespace` 会改变索引，真实协议测试仍能读取。

准入要求同时满足：StatusCode为Good、值为有限标量Double、SourceTimestamp存在、`0 ≤ 接收时间−源时间 ≤ source-max-age`、源时间严格大于该设备最近接受的源时间。默认 `source-max-age=5` 秒，配置不得小于 `1.5×interval`；未来时间零容忍。这是**服务器与采集器UTC时钟同步**的教学假设，时钟偏差可能导致拒收。本步未实现工业时钟同步或偏差估计。

A的Modbus `source_time=null` 保持原有语义，不套用B门槛。B的 `collected_at` 是采集器接收时间，`source_time` 原样保留设备源时间，二者不能互换。ServerTimestamp仅作诊断。

## 拒绝数据如何处理

Bad、Uncertain、缺源、源过旧、未来、重复、倒退、类型/数值不符均不写有效温度，不推进或解除告警；取消pending，保留active。源时间水位来自持久化的有效测量，重启后仍拒绝旧测量，拒收未来时间不污染水位。网络读取在数据库事务之外；诊断、测量和告警（或诊断、拒绝事件和清pending）在一个短事务中提交。

`opcua_diagnostics` 保存线上原始值JSON、VariantType、StatusCode名称和数值、source/server/received三个时间、准入判定和门槛。非有限数值使用字符串诊断表示，数组仍拒绝。asyncua 2.0.1服务端按Bad语义将Value置Null，所以真实Bad测试保存 `null`/`Null`，不会捏造线上不存在的温度。

通信成功与数据可用分开：读取成功但Bad时，`opcua.communication=success`、`quality=bad`、`eligible=false`。`status.last_attempt_status`在B代表有效采集判定，不能当作通信结果。真正连接/读取异常记录communication_error；历史诊断仍可查，不当作新的通信成功。恢复后只由新的有效源测量推进。

## API与页面

- `/api/devices` 声明A四点、B仅temperature；所有latest/history按设备过滤，B查询其他指标返回422。
- B的latest增加 `opcua`：communication、quality、source_freshness、eligible、reason、diagnostic。
- B的 `status.data_age_seconds` 是最后有效测量的源年龄。最新诊断源新鲜度独立计算，新的Bad不会因旧有效温度过期而误标源过期。
- 查询时重新计算源新鲜度；有效门槛取API配置与诊断采集门槛中的较小值。查询不迁移数据库、不清pending、不解除告警；陈旧结果返回unknown。
- A/B告警会话按 `(device_id, metric)` 隔离，两采集器共库互不清计时。
- 页面支持A/B切换，B只显示温度；切换取消旧请求并清掉旧设备展示，延迟响应不覆盖新设备。API失败保留所选设备的历史快照并显示未知。
- 原始值只进入诊断面板，缺源显示“设备未提供源时间，测量新鲜度无法核实”。浏览器使用查询时年龄加单调时钟等待时长，避免旧快照一直显示可用。
- 历史横轴仍为有效测量接收时间，只保存实际接受的测量；本步不把诊断绘入温度曲线。

## 独立练习命令

以下分别在项目根目录的新终端运行。选择未使用的端口和新的练习库，不关闭原有5180/8016/15035服务。采集器与API使用同一个新库路径；现有启动器仍只启动A，B需另开模拟器与采集器。

```sh
# 终端1：B模拟器（85℃用于持续告警演示）
uv run --locked python opcua_simulator.py --port 4841 --value 85

# 终端2：B采集器
uv run --locked python collect_opcua.py --port 4841 --db data/m3-opcua-practice.sqlite3

# 终端3：只读API
uv run --locked python serve_api.py --port 8021 --db data/m3-opcua-practice.sqlite3

# 终端4：前端，在浏览器打开 http://127.0.0.1:5191 后选择电机B
cd frontend
API_PROXY_TARGET=http://127.0.0.1:8021 npm run dev -- --host 127.0.0.1 --port 5191
```

要同时观测A，在另外两个根目录终端运行：

```sh
uv run --locked python simulator.py --port 15041
uv run --locked python collect_temperature.py --port 15041 --db data/m3-opcua-practice.sqlite3
```

仅停止本次B模拟器后，以同一端口替换参数即可注入：

```sh
uv run --locked python opcua_simulator.py --port 4841 --value 70 --quality bad
uv run --locked python opcua_simulator.py --port 4841 --value 70 --quality uncertain
uv run --locked python opcua_simulator.py --port 4841 --value 70 --source-mode missing
uv run --locked python opcua_simulator.py --port 4841 --value 70 --source-mode stale
uv run --locked python opcua_simulator.py --port 4841 --value 70 --source-mode future
uv run --locked python opcua_simulator.py --port 4841 --value 85 --source-mode frozen
uv run --locked python opcua_simulator.py --port 4841 --value 85 --source-mode backward
uv run --locked python opcua_simulator.py --port 4841 --value 77.9
```

每次只启动一条同端口命令。frozen第一次可能是新测量，后续重复拒收；backward首个时间也可能有效，随后倒退拒收。冻结/倒退源最终还会超过5秒，因此诊断会显示过旧。**本版重复源时间立即取消pending，不只是停止推进后等待新源间隔超时；这是更保守的第一版策略，与“重复只不推进”不同。默认读取周期1秒慢于源生成周期0.5秒。**采集间隔若小于模拟器0.5秒周期，重复读取被拒绝是预期行为。`--count N` 可有限次运行；存在拒绝或通信失败时退出码1，Ctrl+C为130。
