# M4.2 文档切块预览验收

## 实现范围

本步读取 manifest 白名单中的5份教学文档，校验 SHA256、文档身份、版本和受限 YAML 元数据，生成切块 JSON、完整输入预览及报告。来源引用仅作为元数据，不展开读取；题集和答案没有导入。未知 product_model 仍为 null。

本步没有生成向量、创建 Chroma、运行检索或调用 LLM；没有 Hit@K 成绩。未操作用户 data、docs/learning、现有采集器或服务。

## 运行命令

在项目根目录运行。当前交付目录为 `preview-v2`，旧 `preview` 保留。以下命令使用新的 `preview-rerun` 目录；复跑时仍需另选尚不存在的目录。

```sh
uv sync --locked
.venv/bin/python -m assistant.knowledge_preview --manifest docs/knowledge/manifest.json --output docs/verification/m4-knowledge-preview/preview-rerun --download-tokenizer
```

首次下载后，去掉 `--download-tokenizer` 可离线运行；默认缓存为 `.cache/knowledge-tokenizer/7999e1d3359715c523056ef9478215996d62a620/`。可用 `--tokenizer-cache` 指定独立缓存。缺资源、下载失败、资源哈希不符均明确报错，不替代为字符计数。

输出目录必须是新目录，且位于语料目录以外。预览先在临时目录构建，再独占创建输出目录，最后发布成功报告；普通写入失败回滚本次输出，已有成功产物不会覆盖。进程被强制杀死时可能留无成功报告的临时/未完成目录，应另选新目录重跑。成功退出码0，运行错误1，命令格式错误2。

## tokenizer 依据及资源

模型固定为 BAAI/bge-small-zh-v1.5，revision 为 `7999e1d3359715c523056ef9478215996d62a620`。[官方模型卡](https://huggingface.co/BAAI/bge-small-zh-v1.5/blob/7999e1d3359715c523056ef9478215996d62a620/README.md)说明正文不需要添加查询指令；本实现只添加可追溯的标题、章节与适用范围前缀。

[官方 tokenizer 配置](https://huggingface.co/BAAI/bge-small-zh-v1.5/blob/7999e1d3359715c523056ef9478215996d62a620/tokenizer_config.json)规定 model_max_length=512。使用 Hugging Face [Tokenizers 的文件加载与编码接口](https://huggingface.co/docs/tokenizers/api/tokenizer)，直接加载该 revision 的 tokenizer.json，包含原模型的 WordPiece 词表、大小写规则、中文处理及 CLS/SEP 后处理；关闭 padding/truncation。没有用 jieba、字符数或其他模型的 tokenizer 代替。

| tokenizer.json | 439125 字节 | 48cea5d44424912a6fd1ea647bf4fe50b55ab8b1e5879c3275f80e339e8fae26 |

## 切块策略与输出语义

- 优先完整二级章节；有实质正文的导言独立保留；仅含文档标题/空白的前导内容合并到首个有正文的章节，保持真实连续来源范围，代码围栏内标题不作为章节边界。
- 300 tokens 为软目标，301～512的完整块标记 `over_soft_target=true`，不为了凑长度拆散短规则。
- 完整输入包含标题/适用前缀、原文及特殊 tokens。长度超过512明确报出文档、章节和实测长度；不截断、不改源文件。本小步不自动拆长表/长规则，超长需人工编辑或后续安全拆分。
- 当前没有拆分章节，因此不添加40-token重叠，不跨文档拼接。仅标题的前导范围附加到首个正文章节，不生成独立可检索块；整篇只有标题而没有正文时明确报错。尚未经召回质量评测。
- `original_text` 是原文件对应连续片段；`embedding_text` 明确包含附加前缀。元数据保留文档ID、版本、teaching_only、设备适用性、未知型号、来源等。
- 字符区间 `[source_start, source_end)` 相对于完整 UTF-8 解码原文，零基且右端不含；行号一基。YAML前置信息不算正文，正文全部字符（包括标题/空白）必须被覆盖，不能只检查关键词。
- chunk_id由版本、内容和策略等确定，不只是编号；同输入同配置重复生成一致，修改输入内容会改变对应ID。

产物为 [chunks.json](preview-v2/chunks.json)、[preview.md](preview-v2/preview.md)、[report.json](preview-v2/report.json)。报告列出 tokenizer revision、文件hash/版本、每份语料hash、完整覆盖、块数、最大长度及超过软目标的块。

## 验证证据

测试覆盖白名单与路径逃逸、哈希和重复ID、非法YAML/结构、null型号、规则/表格/代码块完整、长度边界、稳定ID、正文覆盖、失败时保留源文件及旧结果。真实 tokenizer 检查“中文”含 CLS/SEP 为4 tokens；600个“温”实测602 tokens，证明没有按512静默截断。

R01～R06只进行结构与人工内容核对，具体章节和chunk_id见本目录结构核对记录。核对包括：触发前已有状态、有效新鲜样本与连续性条件；Good与源时效；恢复严格低于阈值而非等于；事务不证明同步测量；全范围统计不等于有限明细；零样本不等于0℃或查询失败。此核对不使用向量检索，不能报告为检索命中。

## 纯标题块修订（v2）

主学习任务复核发现旧25块中有5块仅含文档标题。根因是前导内容无条件成块，原覆盖测试不能识别这个内容质量问题。已先补失败测试，再按是否存在正文决定保留或合并；有实质导言的原用例仍通过。合并后的完整输入继续受512硬上限约束，超长报错。

当前策略 `h2-atomic-v2-merge-title-preamble` 生成20块，最大322 tokens，2块超过300软目标，3955正文字符无损覆盖。策略变更使ID更新；同策略、版本、元数据与内容仍生成稳定ID。来源字符、行号和内容hash按合并后的真实原文切片计算。旧成功产物未覆盖，旧映射见[结构核对-v1.md](结构核对-v1.md)。

本次仅运行受影响的24项knowledge测试，全部通过（真实tokenizer测试未跳过），见[knowledge-tests-v2.txt](knowledge-tests-v2.txt)；没有重复此前157项全回归。新预览的R01～R06共9个章节已重新定位，严格恢复条件及前提仍完整。未运行检索，不能据此声称召回改善或Hit@K达标。
